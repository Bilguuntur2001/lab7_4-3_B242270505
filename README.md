## Хэсэг E: Дүгнэлт (debrief)

Хамгийн үр дүнтэй нь **Fed-Ex** аялал байлаа. Нэг номыг нэмэх → харах → хайх → устгах замаар дагахад 6 согог гарсан: BUG-04, BUG-06, давхар escape, оны validation, давхардал, урт текст. Учир нь нэг өгөгдөл олон газар (хүснэгт, хайлт, мессеж, тоолуур) тусгагддаг. **Supermodel** нь өгөгдөлгүйгээр, зөвхөн эхний дэлгэцийг харахад 4 согог олсон: BUG-02, BUG-03, ногоон Устгах товч, латин "x". **Couch Potato** нь ганц үйлдлээр хамгийн ноцтой validation согогийг (BUG-01) илрүүлсэн. **Saboteur** нь UI-аар хэзээ ч хүрэхгүй API-ийн согогуудыг (BUG-05, DELETE 999 → 200) олсон. Charter-аас гадуур санамсаргүй олдсон зүйл нь хайлтын дараа "Нийт ном" тоолуур шинэчлэгдэхгүй байсан явдал. Шалгагдаагүй үлдсэн зүйлс: олон хэрэглэгч зэрэг ажиллах, гар (keyboard) болон accessibility, гарчиг дээрх Enter товч, Unicode/emoji, маш олон номтой үеийн гүйцэтгэл. Эдгээр нь дараагийн session-ий charter болно. Лаб 1-ийн Playwright маягийн автомат тест нь спецификацид тодорхой oracle-той согогуудыг барих байсан: BUG-01 (мөрийн тоо), BUG-03 (тоолуур = мөр), BUG-04 (хайлтын үр дүн), BUG-05 (статус код), BUG-06 (мессеж). Харин ногоон Устгах товч, латин "x", урт текстээр эвдэрсэн хүснэгт, "1,999" формат зэрэг харагдацын согогийг хэн нэгэн урьдчилан assertion бичээгүй л бол зөвхөн хүний нүд л анзаарна. Эдгээрийг энэ session-д ч charter-т "харагдацын дүрэм"-ийг зориуд оруулснаар л олсон. Эцэст нь энэ session нь автоматжуулсан учраас хурдан, давтагдахуйц байсан. Гэхдээ хүний session-ий гол давуу тал болох ажиглалтаас шинэ санаа төрж чиглэлээ өөрчлөх боломж хязгаарлагдмал байсан.
